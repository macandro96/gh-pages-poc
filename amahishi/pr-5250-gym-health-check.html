Why the stall watchdog never asked NeMo-Gym whether its servers were alive — and how it asks every Gym actor now

NVIDIA-NeMo/RL #5250. Permalinks pin the PR head 4e57ebb; removed code is linked at the base e4af41d.

Before
The watchdog's health check skipped NeMo-Gym in every run. The Gym entry is a shard set, which has no health_check, so no Gym actor was ever asked. A dead Gym server showed up, at best, as a rollout stall after 600 s.
This PR
Reads the Gym entry as a shard set and asks every Gym actor at the same time, each with its own time limit. Each problem is one line that names the actor.
Status
Fixed by this PR. No config key changes. CI ran the check against real Gym actors with no false report.
Background. NeMo-Gym runs its tool and environment servers as subprocesses inside Ray actors (NemoGym). A job can split the servers into shards, each with one or more replicas, and NemoGymShardSet holds all of those actors. A job without shards is a set with one actor. The single controller's stall watchdog wakes every 30 s and, when gym_subprocess_check is on (the default), asks the environments whether they are healthy. Dotted words have a short explanation: hover or tap them.

Setup stores the Gym actors under the key "nemo_gym" as a NemoGymShardSet, for sharded and unsharded jobs alike (setup.py:2445). The old check looked for a health_check method on each entry and skipped any entry without one (base :4524). The method lives on each NemoGym actor, not on the set that holds them, so the Gym entry was always skipped. The figure follows one job: shard tools with two replicas, shards search and code with one each. One tools replica has stopped answering, and the search server process has died.

The fix

Where the fix lands: RL only, in single_controller.py, plus tests. No Gym change: each actor already has a health_check that runs Gym's own server poll; the PR only calls it.

The new method's docstring (head L4531-L4547) is left out of the second hunk.

  1. Read the entry the way the rollout code does. as_nemo_gym_shard_set turns a set or a single actor into a set. Other environments, such as math, have no subprocess servers and are not asked.
  2. Ask every actor, all at once. One gather over all_handles, with a separate time limit per call. A silent actor costs one tick at most and does not hide the others.
  3. Name the actor. instance_label gives the shard name, plus /<replica> when the shard has more than one replica. That is the same name the per-shard log directories use.
  4. Keep a dead server to one line. Ray's error text holds the remote traceback, and Gym's error holds the server's last output. Only the first line of the original error is kept; the full output is in the Gym actor's log.

What it means for a run

Every single-controller run with NeMo-Gym now checks every Gym actor on every watchdog tick. That is one Ray call per actor every 30 s. A dead tool server is named within one tick instead of hiding behind failed rollouts or a 600 s stall.

What happens next is still decided by stall_action. Under the default warn, the run prints the problem on every tick and keeps going. Under abort, it ends with RuntimeError: environment health check failed -- …. Setting gym_subprocess_check: false turns the check off.
